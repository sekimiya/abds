# アーセナルベース（ARMS）カードOCRシステムの開発記録

## はじめに

この記事では、アーセナルベース（ARMS）というカードゲームのカード情報を自動的に読み取るOCRシステムの開発について記録します。このシステムは、カード画像から構造化されたデータを抽出し、ゲームデータベースの構築を自動化することを目的としています。

## プロジェクト概要

### 開発背景
アーセナルベース（ARMS）は、ガンダムシリーズを題材としたカードゲームです。カードにはMS（モビルスーツ）カードとPL（パイロット）カードがあり、それぞれに詳細な能力値やスキル情報が記載されています。これらの情報を手動で入力するのは非常に時間がかかるため、OCR技術を用いた自動化システムの開発に取り組みました。

### システムの特徴
- **多段階OCR処理**: 基本情報の抽出から詳細なスキル分析まで段階的に処理
- **構造化データ出力**: JSON形式で統一されたデータ構造を提供
- **エラーハンドリング**: 処理失敗時の詳細なログ記録
- **拡張性**: 新しいカードタイプやスキルに対応可能な設計

## アーセナルベース（ARMS）のカード種類

アーセナルベース（ARMS）には、大きく分けて以下のカード種類が存在します：

### 1. MSカード（モビルスーツカード）

MSカードは、ゲームの中心となるモビルスーツを表すカードです。各MSには以下の情報が記載されています：

#### 基本情報
- **カードID**: 一意の識別番号（例：FQ01-001）
- **カード名**: MSの名称（例：ガンダム試作3号機）
- **モデル**: 機体の正式名称（例：RX-78GP03S GUNDAM GP03S）
- **コスト**: デッキ構築時のコスト（1-10）
- **カテゴリ**: 機体の分類（近距離、遠距離、機動）

#### 能力値
- **機動力**: 移動力と回避力に影響
- **遠距離攻撃力**: 射撃攻撃の威力
- **近距離攻撃力**: 格闘攻撃の威力
- **HP**: 耐久力

#### 地形適性
- **地上**: A/S/B/C/D（Aが最高）
- **宇宙**: A/S/B/C/D
- **砂漠**: A/S/B/C/D
- **水中**: A/S/B/C/D

#### 武器情報
- **メイン武器**: 主要攻撃手段（射程、攻撃種別）
- **サブ武器**: 補助攻撃手段（射程、攻撃種別）

#### 特殊能力
- **MSアビリティ**: 機体固有の特殊能力
- **リンクアビリティ**: デッキ内の特定カードとの連携効果
- **SP（スペシャルアタック）**: 強力な攻撃技

### 2. PLカード（パイロットカード）

PLカードは、MSを操縦するパイロットを表すカードです。各パイロットには以下の情報が記載されています：

#### 基本情報
- **カードID**: 一意の識別番号（例：FQ01-P01）
- **カード名**: パイロットの名称（例：アムロ・レイ）
- **コスト**: デッキ構築時のコスト（1-5）
- **カテゴリ**: パイロット

#### 特殊能力
- **パイロットスキル**: パイロット固有の特殊能力
- **SQ関連スキル**: スクワッドシステムに関連する能力
  - SQゲージ効果
  - SQUAD RUSH中の効果
  - 発動条件と効果
- **リンクアビリティ**: デッキ内の特定カードとの連携効果

### 3. カードのレアリティ

カードには以下のレアリティが存在します：

- **コモン（C）**: 最も一般的なカード
- **アンコモン（UC）**: やや珍しいカード
- **レア（R）**: 珍しいカード
- **スーパーレア（SR）**: 非常に珍しいカード
- **ウルトラレア（UR）**: 最も珍しいカード

### 4. シリーズ別の分類

カードは以下のようなシリーズに分類されています：

#### メインシリーズ
- **ABシリーズ**: アーセナルベース基本セット
- **FQシリーズ**: フォースクワッドシリーズ
- **LXシリーズ**: レジェンドシリーズ
- **UTシリーズ**: ユニットシリーズ

#### 特殊シリーズ
- **PRシリーズ**: プロモーションカード
- **SPシリーズ**: スペシャルカード
- **限定カード**: イベント限定カード

### 5. カードの特殊効果

#### リンクアビリティ
デッキ内に特定の条件を満たすカードが含まれている場合に発動する効果：
- **デッキ枚数条件**: 「デッキに3枚以上」など
- **シリーズ条件**: 特定シリーズのカードとの連携
- **効果**: 能力値アップ、特殊効果付与など

#### SP（スペシャルアタック）
MSカードの裏面に記載される強力な攻撃技：
- **通常SP**: 基本的なスペシャルアタック
- **SQUAD SP**: スクワッドシステム発動中のSP
- **UNITED SP**: 特定のパイロットとの連携SP

#### USP（Unique Special Power）
MSカードに記載される機体固有の特殊能力：
- **USP名**: 機体固有の特殊能力の名称
- **発動条件**: USPを発動するための条件
- **効果**: USP発動時の効果
- **制限**: 発動回数や条件の制限

#### SQ（スクワッド）システム
パイロットカードのSQ関連スキル：
- **SQゲージ**: スクワッドゲージの増減効果
- **SQUAD RUSH**: スクワッドラッシュ発動中の効果
- **発動条件**: 特定の条件でのスキル発動

### 6. カードの収録情報

各カードには以下の情報も含まれています：

- **イラストレーター**: カードイラストの作者
- **収録弾**: どの弾に収録されているか
- **カード番号**: 弾内での収録順序
- **画像URL**: カード画像のURL

このような多様なカード種類と情報構造を持つアーセナルベース（ARMS）のカード情報を、効率的かつ正確に抽出することが、このOCRシステムの主要な課題でした。

### 使用技術

### システムアーキテクチャ

```
入力: カード画像URL/ファイル
    ↓
1. 基本OCR処理 (extract_structured_data_from_url)
    ↓
2. MSカード抽出 (extract_ms_cards_from_basic_results)
    ↓
3. SP部分OCR処理 (extract_sp_details_from_image)
    ↓
4. PLカードSQ分析 (analyze_pl_sq_skills)
    ↓
出力: 構造化JSONデータ
```

## ChatGPT APIの活用

### OpenAI GPT-4oについて

このOCRシステムの核となる技術は、OpenAIが提供するGPT-4o（GPT-4 Omni）モデルです。GPT-4oは、テキストと画像の両方を理解できるマルチモーダルAIモデルで、画像認識とテキスト生成を同時に行うことができます。

#### GPT-4oの特徴
- **マルチモーダル対応**: テキストと画像の両方を入力として受け取れる
- **高精度な画像認識**: 複雑なレイアウトや小さな文字も正確に読み取り
- **構造化データ出力**: JSON形式での出力に対応
- **日本語対応**: 日本語のテキスト認識と生成に優れている
- **コンテキスト理解**: カードゲーム特有の情報構造を理解

### APIの使用方法

#### 1. 基本的なAPI呼び出し

```python
from openai import OpenAI

client = OpenAI(api_key=api_key)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": "あなたは画像からカード情報を抽出してJSONに変換するOCRアシスタントです。"},
        {"role": "user", "content": [
            {"type": "text", "text": prompt},
            {"type": "image_url", "image_url": {"url": image_url}}
        ]}
    ],
    max_tokens=4096,
    temperature=0.0,
)
```

#### 2. 画像の入力方法

**URLからの画像読み込み:**
```python

```

**ローカルファイルからの読み込み:**
```python

with open(image_path, "rb") as image_file:
    image_bytes = image_file.read()
    image_b64 = base64.b64encode(image_bytes).decode('utf-8')
    data_url = f"data:image/jpeg;base64,{image_b64}"
```

**Base64文字列の直接使用:**
```python

```

## 処理フローの最適化

### 4段階ワークフロー

効率的な処理のため、4段階のワークフローを設計しました：

1. **基本OCR**: 全カードの基本情報を抽出
2. **MSカード抽出**: MSカードのみをフィルタリング
3. **SP OCR**: MSカードのSP部分を詳細処理
4. **SQ分析**: PLカードのSQ関連スキルを分析

この段階的処理により、以下のメリットを実現しました：
- **処理時間の短縮**: 必要なカードのみ詳細処理
- **エラーの局所化**: 段階ごとのエラー管理
- **リソース効率**: API使用量の最適化
