Summary 2 実装要件（たたき台）
更新日: 2025-08-08

1. 目的 / ゴール
- デッキ（MS×5 + PL×5）を視覚的に、素早く、気持ちよく把握できるサマリーUIを提供する。
- 主要メトリクス（総コスト、総HP、総近距離/遠距離攻撃）を一目で確認可能にする。
- 既存のデータ取得APIとCookie保存を流用し、導入コストを最小化する。

2. 対象画面 / エンドポイント
- 画面URL: /summary2
- テンプレート: templates/summary2.html
- ルーティング: app.py に @app.route('/summary2') を追加

3. データ取得と永続化
- 取得API: GET /fetch_cards
  - 返却例: { success: True, images: Card[] }
  - Card（必要参照フィールド）:
    - number: カード番号（例: FQ01-001）
    - name: カード名
    - category: 'MS' | 'PL'（型のフォールバック）
    - front.image_url: 表面画像URL
    - ocr_data: 抽出済みOCR JSON
      - type: 'MS' | 'PL'（優先）
      - cost: number
      - stats.hp: number
      - stats.melee_attack: number
      - stats.ranged_attack: number
- デッキ永続化: Cookie 'gundamAutoSave'
  - 期待構造: { timestamp: string, cards: [{ index:number, number:string, name:string }] }
  - ロード時の挙動:
    1) Cookieが有効かつ cards 配列がある → number 照合で選択カード配列を復元
    2) それ以外 → サンプルデッキ（MS5+PL5）を自動構築

4. UI/UX 要件
- 全体テーマ: ダーク、ガラスモーフィズム風、落ち着いたグラデーションと微光エフェクト
- レイアウト
  - ツールバー
    - タイトル（バッジ付き）
    - 操作ボタン: 「再読込」「画像として保存」
  - メトリクスパネル（4枚のカード）
    - 総コスト（殲滅/制圧/防衛の内訳をタグで表示）
    - 総HP
    - 総近距離攻撃（プログレスバー）
    - 総遠距離攻撃（プログレスバー）
  - ユニット一覧（5カラム・レスポンシブ）
    - 各ユニットカード:
      - ヘッダー: 「n番機」+ 単位総コスト
      - 画像タイル: MS と PL を並列表示、角丸、バッジ（MS/PL）
      - 名称領域: MS と PL の番号+名称を2行で表示
- レスポンシブ
  - 幅1200px未満: 3列
  - 幅800px未満: 2列、メトリクスは2列
  - 幅560px未満: 1列、ツールバーは縦積み
- 操作
  - 再読込: /fetch_cards を再取得し再描画
  - 画像として保存: 当面は print ダイアログ（将来: html2canvas でPNG出力）
- フィードバック
  - ホバー時の軽いエレベーション、境界線色の強調
  - クリック可能要素のカーソル変化

5. 計算仕様
- 型判定: ocr_data.type があれば使用、無い場合は category を使用
- コスト合計
  - 単位総コスト = MS.cost + PL.cost（数値化できない場合は 0）
  - デッキ総コスト = 殲滅/制圧/防衛のカテゴリ別合計の総和
  - カテゴリ内訳: 単位の型（MS または PL のどちらか既知）に基づき加算
- ステータス合計
  - 総HP = 全MS/PLの stats.hp の合計（未定義は 0）
  - 総近距離攻撃 = stats.melee_attack 合計
  - 総遠距離攻撃 = stats.ranged_attack 合計
- プログレスバー正規化
  - 目安: 4000 を 100% として min 5% を下限に丸め（UIが痩せすぎないように）

6. エラーハンドリング / フォールバック
- /fetch_cards が失敗 → 画面にメッセージ表示（JSコンソールにも詳細）
- Cookie が壊れている → 例外を握りつぶし、サンプルデッキにフォールバック
- 画像読み込み失敗 → 非表示 or プレースホルダ（現行は非表示）
- 数値化不能フィールド → 0 として扱う

7. 非機能要件
- 初期描画 < 2.0s（ローカル想定、画像読み込みは除く）
- 主要操作はJS単体で完結、外部ライブラリ不使用（現段階）
- 主要スクリーン幅での可読性/タップ領域を確保

8. 実装ファイル / 構成
- templates/summary2.html: 画面本体（スタイル内包、将来分離可）
- app.py: '/summary2' ルート追加（済）
- 依存 API: '/fetch_cards'（既存）、Cookie 'gundamAutoSave'（既存）

9. テスト観点
- 正常系
  - Cookie あり（10枚復元）/なし（サンプル生成）
  - すべて数値が正しく計上される（コスト/HP/近/遠）
  - 画像URLあり/なしの混在
- 異常系
  - /fetch_cards が失敗/空配列
  - Cookie JSON が壊れている
  - ocr_data 欠損・フィールド型不正
- 表示系
  - 5/3/2/1カラムへのブレークポイント
  - 長い名称での折返し視認性

10. 将来拡張（ロードマップ）
- モーダルでのカード差し替え（summary.html と同格の選択UI統合）
- 並べ替え（ドラッグ&ドロップ）と即時保存
- PNGエクスポート（html2canvas/ライブラリ導入）
- メトリクスの詳細内訳（ユニットごとの寄与、リンク発動の反映）
- テーマ切り替え（ライト/ハイコントラスト）

11. 受け入れ条件（Done 条件）
- /summary2 にアクセスすると、
  - Cookie から復元 or サンプルデッキで5ユニット表示
  - 総コスト/総HP/総近距離/総遠距離が数値表示され、バーが機能
  - 殲滅/制圧/防衛の内訳がタグで表示
  - 再読込ボタンで最新データを取得して再描画
  - 画像として保存ボタンで印刷ダイアログが開く
- 主要3ブレークポイントで崩れない

12. メンテナンス指針
- まず /fetch_cards のスキーマ互換性を最優先（破壊的変更を避ける）
- UI改善は CSS のトークン（色・余白・角丸）を中心に調整し、構造は安定化
- 追加JSは関数粒度で役割を明確化（取得・整形・描画を分離）
